02 · What it handlesFrontend Slides

What the runtime takes off the agent’s plate

  1. Fixed 16:9 stage. Authored at 1920×1080, scaled as one frame on any screen.
  2. Navigation. Keys, clickers, wheel, swipe, and deep links like #/3.
  3. Presenter view. Notes, next slide and a timer, synced across windows.
  4. Print and PDF. One slide per page with every build revealed.
  5. Editing. Fix a typo in the browser and save the file back.

3

Each item appears on a press. These are build steps: class="step".

04 · MarkupFrontend Slides

The whole contract

Slides are sections. Notes and build steps are plain HTML. Everything else is the theme.

<main class="deck">
  <div class="deck-stage">
    <section class="slide" data-label="Title">
      <h1>…</h1>
      <li class="step">…</li>
      <aside class="notes">…</aside>
    </section>
  </div>
</main>

05 · WorkflowFrontend Slides

How an agent builds a deck now

1Scaffold

new-deck writes the file with the runtime inlined.

2Design

Write one theme: grid, type, colour, a few components.

3Write

Fill the sections with the actual content.

4Check

check-deck flags overflow, overlap and contrast.

5Look

Read the screenshots and fix what looks off.

Steps 4 and 5 are the ones the old workflow skipped.
